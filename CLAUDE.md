# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal dotfiles backup + full-machine provisioning for **Ubuntu 26.04 ("resolute", arm64)**.
Everything here is Bash + config files — there is no build system, test suite, or linter.

## Commands
- `bash install.sh` — lightweight bootstrap: **shell + dotfiles only** (zsh, tmux, oh-my-zsh, p10k, core brew CLI, symlinks). Run as yourself, not under sudo.
- `bash provision/provision.sh --dry-run` — **the verification path**. Prints every planned action, makes no changes, needs no sudo. Run this after editing any step script.
- `sudo bash provision/provision.sh` — full machine replication. `sudo env PROVISION_USER=alice bash …` targets a user; `sudo env INSTALL_DESKTOP=1 bash …` adds the desktop/locale/IME set. **The canonical flag reference is `provision/README.md#flags`** (table + how they combine); `provision.sh --help` prints the recipes. Keep those two the owners — don't restate flag syntax elsewhere.
- `bash provision/inventory-export.sh` — run on the **source** machine to regenerate `packages/{apt.list,flatpak.list,Brewfile}` from live state.
- Scripts are **not** executable — always invoke with `bash <script>`.
- `bash smoke-test.sh lint && bash smoke-test.sh dry` — **the re-runnable smoke tier**: shellcheck the whole tree (warning severity; info notes are intentional) + a `--dry-run` matrix asserting exit codes and output markers for every flag scenario. Run after ANY script change. **CI runs both tiers on every push/PR** (`.github/workflows/smoke.yml`, added 2026-09-11): a matrix of `ubuntu-24.04-arm` (the target arch) + `ubuntu-24.04`, shellcheck **pinned to 0.11.0 by sha256** (the version the tree is kept clean against — an unpinned newer shellcheck adds checks and goes red on a no-op commit; upstream publishes no checksum file, so the two hashes are TOFU pins like the kitty key — re-pin both when bumping). **`.gitlab-ci.yml` is the same gate for GitLab** (added 2026-09-12, self-managed instance, docker executor): images pinned by **digest** instead of actions by SHA; the smoke job is arch-agnostic at run time (`uname -m` picks the shellcheck tarball, both hashes in the file) and runs untagged, with an arm64 leg created only when `ARM64_RUNNER_TAG` is set (`rules:`) so a missing runner skips rather than stalls; the container is root and the dry tier refuses a uid-0 target, so the tiers run as a created user. gitleaks there is the official image `v8.30.1@sha256…` with `GIT_DEPTH: 0` and the repo's `.gitleaks.toml` (GitLab's bundled Secret-Detection template reads a different ruleset file — rejected to keep one allowlist); the GitHub action got `GITLEAKS_VERSION: v8.30.1` for parity because it otherwise downloads *latest* at run time. The dry tier asserts **both** CI files exist and run both tiers, so deleting/renaming either can't go unnoticed. Rehearse a CI change locally in a stock container before pushing: `docker run --rm -v "$PWD":/repo:ro ubuntu:24.04` + non-root user + git/curl/xz + the pinned tarball is all it needs. `bash smoke-test.sh verify S4` is the read-only end-state audit for a provisioned box/clone — **pass the runbook's scenario id** and it expands to the tokens (raw tokens and bare `verify` auto-detect still work; `scenario_tokens()` owns the map). Codifies the phase A–D hand audits; never calls Electron `--version`. Contradictory token combos (`full minimal`, `plain copy`, `installsh full`, `plain golden-clone`) are **refused with exit 2** before anything is audited. `bash smoke-test.sh scenarios` prints the live runbook (S1–S15) plus the id → token map and the composition rules.
- **Lint every script you touch with `shellcheck` — not just `bash -n`** (which only catches parse errors; shellcheck catches the bugs that actually bite: unquoted expansions, `$SUDO` redirect gotchas, etc.). shellcheck ships via the Brewfile. Run it from the steps dir so the sourced `lib.sh` resolves: `cd provision/steps && shellcheck -x <script>`. The tree is clean at the warning level; the only remaining notes are **intentional** info-level ones (SC2016 on the `as_user '…$HOME…'` deferred-expansion pattern, SC2024 on root-side `dconf load < "$FRAG"` redirects) — don't "fix" those.

## Layout
- `.zshrc`, `.p10k.zsh`, `.gitconfig` — the dotfiles (symlinked into `$HOME`).
- `install.sh` — lightweight bootstrap (see Commands).
- `provision/` — **canonical** full-machine replication. `provision.sh` is the entrypoint; numbered step scripts in `provision/steps/` (run 10→60), package lists in `provision/packages/`, shared helpers in `provision/lib.sh`. Details in `provision/README.md`.

## Architecture
`provision.sh` sources `lib.sh`, then runs `steps/*.sh` in numeric order, tolerating per-step failure and printing a summary. Order is load-bearing: 10-apt (base) → 20-apt-third-party (Docker/VSCodium/Cursor repos) → 25-docker-rootless (only `DOCKER_ROOTLESS=1`) → 30-brew → 35-rust (rustup) → 36-alacritty (`cargo install` + desktop integration + shell completions + vendored MesloLGS NF font) → 37-claude-code (native installer, stable channel) → 38-kitty (upstream **signed** .txz, fingerprint-pinned) → 50-flatpak (adds Flathub remote) → 55-gnome-dconf (desktop-only) → 60-shell → 80-next-steps (`~/PROVISION-NEXT-STEPS.md` + self-silencing MOTD pointer — persists the manual follow-ups so a golden clone gets them; text = `lib.sh`'s `next_steps_text()`, shared with provision.sh's end-of-run print, and **branched on machine state** — profile, desktop, and whether rootless Docker actually came up) → 90-finalize (only `GOLDEN_IMAGE=1`; leaves step 80's two files alone). There is **no snap step** — Alacritty (the only user snap) is built via cargo, so the machine needs no snapd. `STEPS` in `provision.sh` is **hand-maintained, not a glob**: a new `steps/NN-*.sh` is inert until registered there (it shellchecks and dry-runs clean while never running), so the dry tier asserts both directions — no orphan file, no phantom entry.

`lib.sh` resolves a non-root `TARGET_USER` because cloud-init runs as root but **Homebrew, oh-my-zsh, rustup, and Claude Code refuse to / shouldn't run as root** — those steps drop to that user via `as_user` (a `sudo -u … bash -c` **non-login** shell — deliberately: a non-interactive login bash runs `~/.bash_logout`→`clear_console`, which fails without a tty and corrupted exit statuses; fixed in `0fa9b9c`). An explicitly-set `PROVISION_USER` **must exist or `lib.sh` dies** (catches a cloud-init typo before provisioning the wrong account; `--dry-run` only warns). Unset, it falls back `SUDO_USER` > uid 1000 > `ubuntu` — and **the fallback result is checked too**: if even `ubuntu` doesn't exist (no non-root user on the box) it dies the same way rather than provisioning into an empty `TARGET_HOME`. This repo never creates users; cloud-init's `users:` owns that.

### Editing step scripts — the helper contract
Every mutating action must go through a `lib.sh` helper so `--dry-run` stays accurate and runs stay non-interactive/idempotent. **Calling `apt-get`, `curl … | sudo tee`, etc. directly silently breaks `--dry-run`.**
- `run <cmd>` — runs a plain command, or prints `[would] …` under dry-run.
- `apt_get <args>` / `apt_install <pkgs>` — non-interactive apt (returns real status / tolerant). Wrapped in `env` so noninteractive+needrestart survive `sudo`, with `--force-conf*` and `DPkg::Lock::Timeout=600`.
- `as_user <cmd>` — run as `$TARGET_USER` via login shell (brew, oh-my-zsh, dotfile symlinks).
- For anything with pipes/redirects (key downloads, repo files), guard manually: `if dry; then would "…"; else …; fi`.
- `log`/`warn`/`die` for output; `dry`, `is_root`, `$SUDO`, `load_brew` are also provided.

### Terminals — two, installed differently on purpose
Alacritty (step 36) is **built** via `cargo install` because upstream ships **no Linux binary at all** (v0.17.0's release assets are Windows/macOS plus man pages, completions, terminfo and the icon — which is exactly why step 36 fetches those ancillary files from the matching tag). kitty (step 38) is the opposite case: upstream publishes a per-arch `.txz` **and a detached OpenPGP signature**, so it is installed from that bundle and **verified against a pinned fingerprint** (`3CE1780F78DD88DF45194FD706BC317B515ACE7C`, Kovid Goyal) — a mismatch skips the install rather than falling back to unverified. Two checks, deliberately: the same fail-closed `verify_keyring` pattern step 20 uses for apt keys, **plus** `gpg --verify --assert-signer "$KITTY_FP"` on the tarball itself. The second is not redundant — `verify_keyring` compares only the *first* key in the file, so a `kovid.gpg` with the real key first and an attacker key **appended** passes the pin, and a bare `gpg --verify` would then accept a tarball signed by either; `--assert-signer` is what binds the signature to the pinned fingerprint (TODO I). That makes kitty the only artifact here verified by **signature** rather than by checksum-over-TLS — the others are **not** unverified, and the distinction is narrower than "crates are unsigned": cargo checks the sha256 `cksum` from the crates.io index (step 36 also passes `--locked`, which pins the dep tree), rustup checks the per-artifact `hash =` in Rust's channel manifest (Rust publishes `.asc` files too, but rustup does not check them by default), and Claude's installer pulls a per-version manifest and **fails closed** on a `sha256sum` mismatch (`rm` + `exit 1`). All three abort on mismatch. The real difference: in every one of those the hash is served by the **same host** as the artifact, so the check does not survive that host being compromised, whereas kitty's pinned fingerprint lives in **this repo** (the key itself is fetched over TLS on first use — TOFU; the pin is what carries the weight). The one genuinely unverified link in the tree is rustup's **bootstrap**: `sh.rustup.rs` fetches `rustup-init` over TLS with no checksum at all. Other paths were checked and rejected: **cargo** N/A (kitty is C+Python/Go), **brew** has no Linux formula (404, macOS cask only), **apt** is frozen (0.45.0 vs 0.48.2 — the same reason apt was rejected for Alacritty), **flatpak** doesn't carry kitty and would sandbox the user's shell. Step 38 deliberately does **not** write `~/.config/xdg-terminals.list`: which terminal is default is a user preference, not a provisioning decision. Both skip whenever no GUI is wanted — `PROFILE=minimal` or `HEADLESS=1`, via lib.sh's `gui_wanted`.

### Ported dotfiles & configs
Both `install.sh` and step 60 install a shared set into `$HOME` — the file set is listed **once** in `dotfiles.list` at the repo root (single source of truth both read, so they can't drift): `.zshrc`, `.p10k.zsh`, `.gitconfig`, `.tmux.conf`, `.config/alacritty/alacritty.toml`, `.config/nvim/` (whole LazyVim tree; `lazy-lock.json` excluded so plugins track latest), and `.claude/{settings.json,statusline-command.sh}` (the repo mirrors `$HOME` layout; nested parents created; manifest entries may be files or whole directories). Default is **symlink** (repo stays source of truth); `DOTFILES_COPY=1` / `install.sh --copy` / `GOLDEN_IMAGE=1` **copy** instead (self-contained). The Alacritty theme repo is **cloned, not vendored** (step 36 / install.sh → `~/.config/alacritty/themes`). The **MesloLGS NF** Nerd Font, by contrast, **is** vendored (`fonts/MesloLGS-NF/` — no apt/brew package exists for it on Linux/arm64, and alacritty.toml pins it as the font family), copied into place system-wide by step 36 and into `~/.local/share/fonts` by install.sh (`.gitleaks.toml` allowlists the binary `.ttf` path). GNOME settings live in `provision/gnome/dconf-settings.ini`, applied by step 55 via `dconf load` **only when `INSTALL_DESKTOP=1`**. `.gitignore` keeps `.claude/` ignored *except* those two tracked files, and blocks the AI/API token files the config audit surfaced (`**/auth.json`, `**/.credentials.json`, `.claude.json`, `.codex/`, etc.). Configs with hardcoded `/home/<user>` paths are templated to `$HOME` so they survive a different target username.

### Modes (env flags)
- `--dry-run`/`-n` — preview only, no changes, no sudo, no network.
- `INSTALL_DESKTOP=1` — also install the desktop/locale/IME apt set + run the GNOME dconf step (55).
- `APT_UPGRADE=1` — before installing, `apt-get upgrade` the packages already on the box (step 10, right after `apt update`). **Off by default**: a blanket upgrade also bumps the installed kernel/grub/shim point-releases step 10 otherwise avoids (initramfs rebuild + a reboot-required flag provision.sh never acts on), so it is opt-in. Uses `upgrade` not `full-upgrade` (no new kernels), runs prompt-free via the noninteractive wrapper, and is convergent/idempotent. For a current golden image or a stale fresh box; cloud-init users can instead set `package_upgrade: true`. A reboot may be wanted afterward (a golden clone reboots anyway).
- `GOLDEN_IMAGE=1` — build a reusable image: implies **STRICT** (first real failure aborts), step 60 **copies** dotfiles instead of symlinking (self-contained), and the **finalize** step (90) resets machine-id / SSH host keys / cloud-init state / logs / history. Destructive — throwaway build box only. Clone the repo **and** write run logs under `/tmp` (finalize wipes `/tmp` last → auto-removed); finalize does **not** touch `$HOME`, but **warns** about a leftover repo / `*.log` there (hidden repos like `~/.oh-my-zsh` are skipped) so it isn't silently baked into the image.
- `DOTFILES_COPY=1` (or `install.sh --copy`) — copy dotfiles into `$HOME` instead of symlinking, *without* the rest of golden-image mode (`GOLDEN_IMAGE` implies it).
- `PROFILE=minimal` — lean headless agent box: steps 36-alacritty + 50-flatpak skip, step 20 skips the GUI editors (VSCodium/Cursor; **Docker stays**), steps 10/30 swap in `apt.minimal.list` / `Brewfile.minimal` (gh/gitleaks/jq/mise/ripgrep/shellcheck; rust via step 35, node via mise — `mise use -g node@lts`, replaced nvm 2026-09-11 — claude via step 37). zsh+p10k+dotfiles kept — `.zshrc`'s bat/eza/zoxide niceties are `command -v`-guarded so the lean shell starts clean; `next_steps_text` drops the font bullet. Value validated (`full|minimal`, else die); **conflicts with `INSTALL_DESKTOP=1` (die)** — a minimal box has no GUI, and allowing both would half-install the desktop set.
- `HEADLESS=1` — the **full manifests with no GUI installs** (added 2026-09-11): the shared human+agent headless box. Implemented as a second axis, not a third profile: `PROFILE` picks the manifests (steps 10/30 key on `minimal`), and lib.sh's **`gui_wanted`** (`! minimal && HEADLESS != 1`) gates every GUI install — 36-alacritty, 38-kitty, 50-flatpak, and the VSCodium/Cursor block of step 20 — with `no_gui_reason` supplying the skip marker (`PROFILE=minimal` or `HEADLESS=1`; the dry tier asserts both). A new GUI step needs one line: `gui_wanted || { log "x: skipped ($(no_gui_reason))"; exit 0; }`. `HEADLESS=1 ⊥ INSTALL_DESKTOP=1` (die); `HEADLESS=1` + `PROFILE=minimal` is redundant and accepted. `next_steps_text`'s font branch keys on `gui_wanted` (the font follows the GUI), and `verify` auto-detect reads the flag back from that note. Verify vocabulary: `headless` is an ADD-ON to `full` (`v_full_cli` + `v_no_gui` instead of `v_gui`); scenario **S15 — LIVE-PASSED 2026-09-12** (fresh arm64 26.04 at `1844563`: `✅ no failures`, `verify S15` 38/38, zero warnings in the log; `exec zsh` silent with `atuin init` + `mise activate`; glab/dive/ktop/atuin all run; `mise use -g node@lts` → node 24.21.0 + corepack, `mise use -g go@latest` → go 1.27.1, `which` shows mise as the sole owner of both).
- `DOCKER_ROOTLESS=1` — set up rootless Docker for `TARGET_USER` (step 25): runs the official `dockerd-rootless-setuptool.sh` as the user, enables linger + the `--user` service, and sets the `rootless` context. Needs the step-20 prereqs (`uidmap`, `docker-ce-rootless-extras`, `dbus-user-session`) and **unprivileged user namespaces** (host-dependent — soft-fails where userns is restricted; rootful Docker still works). On Ubuntu 24.04+/26.04 the restriction is AppArmor's `apparmor_restrict_unprivileged_userns` (on by default even when the `unprivileged_userns_clone` sysctl is `1`); relax it with a `sysctl.d` drop-in (`=0`) + `sudo sysctl --system` to enable rootless on clones. Do **not** also `usermod -aG docker` (that's the root-equivalent rootful path).
- Failure handling: tolerant helpers call `soft_fail` → warns + records to `$SOFT_FAIL_LOG`; a normal run completes every step but **exits non-zero** if any soft failure occurred. Under `STRICT`/`GOLDEN_IMAGE`, `soft_fail` and a failing step **die** immediately. `lib.sh` refuses a root/uid-0 `TARGET_USER`.

## Conventions / gotchas
- `provision.sh` is cloud-init-ready: root, idempotent, failure-tolerant. `--dry-run` previews with no changes and no sudo.
- Step 10 filters boot/kernel/third-party/desktop out of `apt.list` at install time (the list is the full `apt-mark showmanual` set on purpose); step 20 owns Docker/VSCodium/Cursor in **key → verify → repo → install** order — those packages have no repo at step 10. The repo add + install are **gated on a valid signing key** (`verify_keyring`): Docker, Cursor, and VSCodium fingerprints are all pinned (`DOCKER_FP`/`CURSOR_FP`/`VSCODIUM_KEY_FP`, each verified against the live key). A failed/mismatched key `soft_fail`s and skips that vendor rather than adding a half-configured repo. The post-repo index refresh is per-vendor and resilient (`vendor_apt_update`: only that vendor's source, retries, persistent failure warns even under STRICT — see TODO E, done). (Bruno was removed from the project — use httpie / VSCodium extensions instead.)
- Step 30 filters the `Brewfile` to `tap`/`brew`/`cask` lines; `flatpak`/`npm`/`mas`/`vscode` entries from `brew bundle dump` are dropped (flatpaks are owned by `flatpak.list`).
- `bat` must come from **brew** (binary `bat`); apt's is `batcat` and breaks `.zshrc`'s `alias cat="bat"`.
- **Casks are kept** in the Brewfile — Linux-capable casks (e.g. `codex`) install on linuxbrew arm64; macOS-only casks fail-soft.
- Arch-aware fallbacks: Docker codename falls back to `noble`. Cursor uses its signed apt repo (`downloads.cursor.com/aptrepo`, suite `stable`, both arches — codename-agnostic).
- Homebrew is hardcoded at `/home/linuxbrew/.linuxbrew`. The omz `jj`/`bun` plugins only add completions; a missing tool just warns.
- **Never committed** (see `.gitignore`): SSH/GPG keys, `~/.claude/`, cloud creds, shell history. `.gitconfig` ships a placeholder identity — set the real one.
- **License: AGPL-3.0-only** (added 2026-09-11). `LICENSE` is the verbatim FSF text (sha256 `0d96a4ff…abcb0`, same as Debian's `common-licenses/AGPL-3`) — **never edit it**; GitHub's detection needs it byte-exact. The copyright notice and the plain-English summary live in README's `## License`, which owns that fact. Vendored components keep their own licenses and are independently usable under them: `fonts/MesloLGS-NF/` and `.config/nvim/` are Apache-2.0 with their own LICENSE/NOTICE files, `.p10k.zsh` derives from powerlevel10k (MIT) — never relicense them or strip those notices. `-only` rather than `-or-later` is deliberate: a future AGPLv4 applies only if the owner adopts it. PolyForm Noncommercial 1.0.0 was the considered alternative (limits for-profit use) and was declined in favour of being genuinely open source; AGPL permits commercial use and deters corporate adoption only by policy.
- **Secret scanning** (defense-in-depth beyond the filename-based `.gitignore`): `gitleaks` (in the Brewfile) scans content. A versioned pre-commit hook lives in `.githooks/` — enable per clone with `git config core.hooksPath .githooks`. CI runs `.github/workflows/gitleaks.yml` on push/PR. `.gitleaks.toml` allowlists the pinned public key fingerprints (Docker/Cursor/VSCodium). The hook prefers `gitleaks git --staged`; CI scans full history.

- [ ] **G — `versions.lock`: record what was installed, don't force it.** Raised 2026-09-06 while auditing what this repo pins. Goal is the tagging/versioning story: make a golden image **auditable and diffable** ("what changed between Gen-1 and Gen-2") without pretending to bit-for-bit reproducibility the toolchain cannot deliver.
  - **Current pinning status** (audited, not assumed): pinned = 4 GPG fingerprints (`DOCKER_FP`/`CURSOR_FP`/`VSCODIUM_KEY_FP`/`KITTY_FP`), 2 CI actions at commit SHAs, Cursor's repo `Architectures:`, and the MesloLGS NF family in `alacritty.toml` — all **identity**, never **version**, all fail-closed. Floating by design: Brewfile (26 formulae), `flatpak.list`, the alacritty crate (`--locked` pins only its *dep tree*, not alacritty's own version), rustup `stable`, Claude `stable`, kitty `current-version.txt`, alacritty themes at `HEAD`. `apt.list` is names-only, so it is pinned by the **Ubuntu release**, not by this repo — the one group already deterministic for a given image.
  - **THE CONSTRAINT — Homebrew cannot be version-pinned, and this is structural.** Verified: `git-delta@0.19`, `neovim@0.11`, `ripgrep@15` all **404** on formulae.brew.sh — versioned formulae exist only where maintainers deliberately made them (`python@3.11`, `node@20`), not for ordinary CLI tools. `brew pin` freezes an **already-installed** version against upgrade; it cannot install an old one. The Brewfile DSL has **no version field**. Short of checking out homebrew-core at a git SHA (unsupported, and old bottles age out), those 26 packages — the largest single group — are unpinnable. Everything else *is* pinnable: apt (`pkg=version`), cargo (`--version X.Y.Z --locked`), rustup (`--default-toolchain 1.98.0`), kitty (version is in the URL), Claude (its installer accepts `[stable|latest|VERSION]` — read from the script), flatpak (`--commit=`), themes (git SHA).
  - **So do NOT add a `PIN_VERSIONS=1` install mode.** It would be ~70% real with an **invisible** 30% hole, and a flag that *reads* as reproducible while brew silently floats underneath is worse than no flag. It would also contradict the packer/chezmoi record above, which says bit-for-bit pinning "belongs in a separate build layer on top — never in `provision.sh` itself".
  - **Do this instead.** (a) Emit `versions.lock` at the end of a run recording what actually landed — `brew list --versions`, `rustc`/`cargo`, `claude --version`, `kitty --version`, `dpkg-query -W` for the third-party debs, `flatpak info`. (b) "Pin mode" becomes **assert mode**: re-run against a recorded lockfile and report **drift**, never force-install old versions. That is 100% achievable, tells no lies, and composes with golden images and cloud-init. (c) Combined with repo tagging, the honest claim becomes *"tag vX built on DATE produced these versions"* — deterministic **inputs** (lists, steps, key pins) plus a recorded manifest of **outputs**. Natural home: extend `inventory-export.sh`, which today exports package **names only**. Keep it cred-free like everything else.

## Project direction & philosophy
- **Two entry points, both first-class:** `install.sh` = lightweight shell+dotfiles on an *existing* box; `provision/` = full machine / cloud-init / golden image. They share the dotfile set via `dotfiles.list`.
- **Bring-to-latest is intentional, not a gap:** brew / `cargo install` / `rustup` / Claude+Cursor stable channels all float. "Reproducible" here means *re-runnable to the same state* (idempotent), **not** version-pinned. Don't add default version pins. Bit-for-bit pinning, if ever wanted, belongs in a separate build layer on top — never in `provision.sh` itself; that layer was evaluated and declined (see the packer/chezmoi entry in Open TODOs, including what would make it worth revisiting).
- **The repo's dual role is permanent** (and is why no build/dotfile-manager layer was adopted on top — see Open TODOs): (1) fresh Ubuntu → clean, cred-free state — no golden image is built from the owner's daily box because it holds creds; (2) a re-runnable "bring-to-latest" layer on top of an existing golden image to keep it current.
- **No creds/PII ever** — enforced by `.gitignore` + the package-names-only `inventory-export.sh`.
